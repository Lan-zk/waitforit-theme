## E1 全新模板系统的选择规则与合并行为

- **问题**：kind→模板选择是否如文档；params 是否深合并；主题 menus/i18n 是否生效。
- **结果**：`public\index.html` 用 `home.html`；`about\index.html` 用 `page.html`；`posts\index.html` 用 `section.html`；`posts\a\index.html` 用 `posts\page.html`；`404.html` 用 `404.html`；baseof 与 `{{ define "main" }}` 正常拼接；shortcode 正常展开。
- **params（关键）**：`shared=site-shared`（站点胜）、`themeDefault=theme-value`（主题默认保留）、`nested.a=site-a`、`nested.b=theme-b`、`siteOnly=site-value` ⇒ **嵌套 map 深合并**。
- **menus**：站点未定义 `menus.main` 时主题菜单生效（输出 `Theme Menu`）；站点定义同名菜单后**只剩站点条目** ⇒ 整体替换，非合并。
- **i18n**：主题 `i18n/en.toml` 生效（`Hello from theme i18n`）；缺失键渲染为空串。
- **集合**：`.Site.RegularPages`=2、`.Site.Pages`=6（含 home/section 与默认 taxonomy 页）。
- **副产品错误**：在主题 `hugo.toml` 同时写 `[menus.main]`（表）与 `[[menus.main]]`（数组表）→ `unmarshal failed: toml: key main already exists as a table, but should be an array table`；只写数组表正常。
- **结论回填**：TPL-01–TPL-12、CFG-03、CFG-07、CFG-09、CFG-11、CNT-06。

## E2 只保留 `all.html`

- **操作**：删除 `page.html` 与 `posts\page.html`，新增 `layouts\all.html`（输出标记 `ALL`）。
- **结果**：`about`、`posts\a` 均由 `all.html` 渲染。
- **结论**：`all.html` 是有效兜底。⇒ TPL-09。

## E3 `list.html` 与 `all.html` 同时存在

- **操作**：删除 `section.html`，保留 `list.html`（标记 `LIST`）与 `all.html`（标记 `ALL`）。
- **结果**：`posts\index.html` 输出 `LIST`；taxonomy 列表页也用 `list.html`；日志报 `Template /all.html is unused`。
- **结论**：`list` 优先于 `all`；两者并存时 `all.html` 会被 `--printUnusedTemplates` 点名，在 `--panicOnWarning` 下会让构建失败（本项目若保留双模板必须接受这一点）。⇒ TPL-09、TPL-14。

## E4 无匹配模板

- **操作**：删除 `page.html`、`single.html`、`all.html`，构建时不加 `--panicOnWarning`。
- **结果**：exit code **0**；日志：`WARN found no layout file for "html" for kind "page": You should create a template file which matches Hugo Layouts Lookup Rules for this combination.`；`public\about\` 不存在（页面静默消失）。
- **结论**：模板缺失**不是**构建错误，`WARN` 是唯一信号。⇒ TPL-15。

## E5 无匹配模板 + `--panicOnWarning`

- **操作**：同 E4，追加 `--panicOnWarning`。
- **结果**：`panic: found no layout file for "html" for kind "page": …`，exit code **2**，`public\` 无产出。
- **结论**：`--panicOnWarning` 是让"静默缺页"变硬失败的唯一开关；本项目 CI 必须开。⇒ TPL-15、REL-07。

## E6 主题声明不兼容的版本

- **操作**：主题 `hugo.toml` 设 `[module.hugoVersion] min = '0.999.0'`。
- **结果**：exit code **0**；日志：`WARN Module "wt-smoke" is not compatible with this Hugo version: Min 0.999.0; run "hugo mod graph" for more information.`；页面正常产出。
- **结论**：版本护栏只 WARN，不阻断；必须靠 `--panicOnWarning`。⇒ CFG-15、CFG-16、REL-03。

## E7 taxonomy / term 页

- **操作**：给 `about.md` 加 `tags: ["red"]`，先不提供 taxonomy/term 模板。
- **结果**：日志出现两条警告（kind `taxonomy` 与 kind `term` 各一条，形如 `WARN found no layout file for "html" for kind "taxonomy": …`）；补 `taxonomy.html` + `term.html` 后，`tags\index.html`、`tags\red\index.html` 正常渲染。
- **结论**：有 taxonomy 数据就会生成页面，缺模板即 WARN；主题必须提供两个模板或由站点关闭 taxonomy。⇒ TPL-06、CNT-06。

## E8 旧路径 `_default/`

- **操作**：删除其他 page 模板，只留 `layouts\_default\page.html`（标记 `legacy-default`）。
- **结果**：`about` **确实**用该文件渲染；但日志报 `Template /_default/page.html is unused`；加 `--panicOnWarning` 后 panic。
- **结论**：0.168.0 仍存在 legacy 回退，与文档"已删除"表述冲突；本项目禁用旧路径（会报 unused + 构建红），理由记录在 TPL-02。⇒ TPL-01、TPL-02。

## E8b 根目录 `single.html`

- **操作**：只留 `layouts\single.html`。
- **结果**：`about`（kind=page）由 `single.html` 渲染。
- **结论**：`page → single → all` 回退链成立。⇒ TPL-09、TPL-12。

## E9 旧目录 `layouts/partials/`

- **操作**：把 `head.html` 移到 `layouts\partials\head.html`（baseof 仍 `{{ partial "head.html" . }}`）。
- **结果**：构建成功、title 正常，**无任何警告**。
- **结论**：旧 `partials/` 目录在 0.168.0 仍被查找（文档称已移除）；本项目仍禁用，理由同 TPL-03（一致性 + 审计口径），不是功能限制。⇒ TPL-03。

## E10 `partial` 返回值与变量作用域

- **操作**：`_partials\ret.html` 内容 `{{ return "ret-value" }}`；`home.html` 的 `define "main"` 内写 `{{ $v := partial "ret.html" . }}ret=[{{ $v }}]`；`partialCached` 同样试一次。
- **结果**：输出 `ret=[ret-value]`；`partialCached` 也返回该值。
- **反例**：把 `{{ $v := partial ... }}` 写在 `{{ define "main" }}` **之前**/之外 → `ERROR error building site: "…\home.html:3:1": parse of template failed: template: home.html:3: undefined variable "$v"`，**exit code 1**（ERROR 级，不是 panic）。
- **结论**：partial 的 `return` 可返回任意值并被调用方接收；变量赋值必须在 `define` 内。⇒ TPL-17。

## E12 `layouts/` 下的残留文件

- **操作**：在 `layouts\` 放 `page.html.bak`。
- **结果**：日志 `WARN Template /page.html.bak is unused`；加 `--panicOnWarning` 后 exit 2。
- **结论**：`layouts` 下任何文件都会被当模板解析；备份/草稿文件会让 CI 变红。⇒ TPL-14。
